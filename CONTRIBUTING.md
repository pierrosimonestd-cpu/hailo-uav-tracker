# Contributing

## Setup

```bash
git clone https://github.com/pierrosimonestd-cpu/hailo-uav-tracker
cd hailo-uav-tracker
pip install -e ".[dev,onnx,bench]"
pre-commit install
```

You do not need a Hailo device, a Raspberry Pi or a turret to work on most of
this. The tests, the tracker, the controller and the simulator all run on a
laptop with no accelerator — that is deliberate, and worth preserving.

## Before opening a pull request

```bash
ruff check src tools benchmarks tests
ruff format src tools benchmarks tests
pytest tests
```

If you touched the wire protocol, also build the firmware conformance test:

```bash
c++ -std=c++17 -Wall -Wextra -Werror -I firmware/esp32_pantilt \
    tests/firmware/test_protocol.cpp -o /tmp/test_protocol && /tmp/test_protocol
```

## House rules

**Numbers come from scripts.** Every figure in the documentation is generated by
`benchmarks/make_report.py` from a JSON file in `benchmarks/results/`. Do not
hand-edit a table; run the benchmark and regenerate. CI enforces this.

**Label what kind of number it is.** `measured`, `simulation` or `published`,
with the hardware stated. A simulation result presented as a measurement is the
one thing this repository will not carry.

**The Raspberry Pi runtime stays light.** `src/uavtrack/` core dependencies are
NumPy, OpenCV, PyYAML and pyserial. PyTorch, ONNX Runtime and the benchmark
stack are optional extras. If you need PyTorch in the inference path, it belongs
in a backend behind `DetectorBackend`.

**Test the failure, not the feature.** The valuable tests here are the ones that
pin down a specific way something breaks: a byte dropped on the serial link, a
frame missed by the detector, an integrator charging against a travel limit.

**Explain the non-obvious.** A comment should say why the code is the way it is,
especially where an obvious alternative is wrong. The two unstable feed-forward
formulations in `docs/control-design.md` are the model: both look correct, and
the write-up is what stops someone "simplifying" back into them.

## Where things live

| You want to change | Look in |
|---|---|
| A detection backend | `src/uavtrack/detect/` |
| Association or track lifecycle | `src/uavtrack/track/` |
| Gains, feed-forward, servo model | `src/uavtrack/control/` |
| The wire protocol | `src/uavtrack/io/protocol.py` **and** `firmware/esp32_pantilt/protocol.h` |
| A benchmark | `benchmarks/` |
| Dataset handling | `src/uavtrack/data/`, `tools/` |

The protocol lives in two places by necessity. Change both, and run the
conformance test.
